# /timeline 信息架构提案（UX Proposal Only）

> 阶段：Wave 1.5 / Canonical Story Alignment — Task 6
> 性质：**proposal，不实现**。基于 inventory/mapping 的调研结论提出 /timeline 新信息架构草案。
> 现状基线：guide 模式为"单卡阅读器 + 上一节/下一节"（见 architecture reality summary #8）；deep link 为 /timeline?beat={event_slug}（#9）。

## 0. 设计目标（来自任务书）

1. 默认体验必须是**连续纵向滚动**；
2. 滚动顺序与 **Canonical Story**（游戏原生任务线）对齐；
3. 点击只负责**深挖**，不负责"去下一幕"；
4. 人物、暗线、历史、完整解析从**主线节点展开**；
5. 保留现有 **deep link** 能力；
6. 保留 **spoiler / visibility closure**。

## 1. 信息架构草案（三层）

### 第一层 · 主线卷轴（默认）
- 整条页面 = 一条连续纵向时间线，节点顺序 = canonical 主线顺序：
  序章（江晏出逃→无相皇→夺玉）→ 篇一·又见新来燕（竹林旧居→断桥→北竹林→百草野→将军祠擂台）→ 神仙不渡段（朱八碗→揭穿胡为→酒窖→医馆井→寻心）→ 篇二·匹马映林嘶（回神仙渡→不羡仙→瓷窑/地下仓库→鬼寺→医馆/弱水岸→寒姨房→破庙→舞马人）→ 不羡仙大火 → 篇三·菱花尘满（酒香塔留信）→ 篇四·为谁归去（破庙汇合→救人→酒香塔千夜）。
- 每个节点是一张"主线卡"：篇标题 + 任务名 + 稳定剧情节点名 + 一句话摘要 + 展开入口（+）。
- **滚动即阅读顺序**；页面底部不再有"下一节"按钮——下一幕就是滚动可见的下一张卡。
- 幕次导航（现有左侧卷签）降级为**页内锚点目录**（点击跳到对应卡，仍是"深挖/定位"，不是"翻页"）。

### 第二层 · 从主线节点展开（点击 = 深挖）
点击任意主线卡展开（accordion / 就地展开 / 右侧抽屉三选一，建议就地展开保持滚动连续）：
- **人物**：该节点出现的人物列表 → 链接到 /characters/{slug}（保留现有深链）；人物卡内嵌"初识→剧情足迹→关系→完整解析"层级（复用 Wave 1 G3）。
- **暗线**：该节点对应的明暗故事·清河内容（清风驿之变/绣金楼/田英）→ 在暗线节点处以标记牌呈现，显式标注"暗线内容，剧透等级 N"。
- **历史**：历史对照卡（如中渡桥之战节点下展开 3 张历史卡，复用现有 HistoricalContext 组件与 /history/{slug} 深链）。
- **完整解析**：人物/节点的完整解析仅由**显式 Reveal 按钮**触发（复用人物级 Reveal 语义：UI 呈现层门控 + unrestricted 阅读上下文；字段级权限模型仍属 Wave 2）。

### 第三层 · 完整事件模式（保留为次级视图）
- 保留现有"完整事件"模式（章节筛选 + 扁平列表）作为**对照视图**，从卷轴页顶部的 tab 进入；默认仍是主线卷轴。
- 事件模式与主线卷轴共享同一 canonical 顺序，避免两套次序。

## 2. 顺序与 Canonical 对齐
- 节点顺序直接由 canonical 层（quest/quest-node）驱动（见 decision memo 方案 A）；当前 guide 的 arc beat 顺序在 canonical 层就绪前作为降级来源。
- 所有未决节点（inventory §7 的 UNRESOLVED）在 UI 上以"待考"样式占位，不插入猜测内容。

## 3. deep link 保留与升级
- 保留 /timeline?beat={event_slug}（向后兼容，现有 e2e/人物页/历史页深链不断）。
- 新增 /timeline?node={canonical_slug}（canonical 层就绪后）：直接定位到任务/任务节点卡，滚动并高亮。
- 深链解析由"逐个请求 arc 详情比对"改为"请求 canonical 索引"（一次性），降低 N+1 请求。

## 4. spoiler / visibility closure 要求（不弱化）
- 进度切换仍整体 remount 阅读面（保留 T05 行为），受限节点标题/摘要/展开内容全部从响应与 DOM 中移除。
- canonical 节点沿用 visible_after_progress + spoiler_level + status 三件套；暗线/历史/完整解析的可见性随其父节点裁剪（复用 H1/H2 闭包模式：Link→Node→Quest→Chapter 四层）。
- 完整解析与暗线卡在默认进度下**不渲染标题**（标题即剧透，沿用现有"不残留残片"标准）。

## 5. 明确不做（本提案范围外）
- 不新增路由（/read 等）；仍以 /timeline 为唯一入口。
- 不实现字段级 Reveal（Wave 2）、不实现问题引擎、不实现多故事线。
- 不重构图/人物/历史页面；本提案只针对 /timeline 的 IA 与交互模式。

## 6. 与 Wave 1 语义边界的兼容性
- 提案保持"剧情足迹 = 自动聚合（beat 派生）"与"人物线 = 人工撰写（Wave 2）"的既有语义约定。
- 提案不触碰冻结数据集：canonical 顺序先以研究文档 + 后端投影实现，dataset 演化留待 Lead 决策。
