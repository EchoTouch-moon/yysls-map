# Task Plan: 清河故事导读与历史背景垂直切片

## Goal

在现有防剧透事件时间线上增加一条可连续阅读的清河主线导读，并为关键事件提供事实边界清晰、来源可核验的历史背景卡，形成“读故事—理解因果—查看历史语境—核对来源”的完整体验。

## Scope Guard

- 核心功能：同页提供“跟着故事读 / 完整事件”双模式；一条人工策划的清河主线；导读节点的叙事角色、承接、重要性和新问题；全链路防剧透。
- 核心前置：将作品事实、历史事实、可信对照和编辑推测显式分开；历史断言必须有独立可靠来源。
- 增强功能：只实现一个关键事件的 2—3 张历史背景样板卡，不扩成历史百科。
- 未来方向：多故事线、全章历史双轴、地图联动、自动考据和 AI 自动发布均不在本轮实现。

## Phases

- [x] Phase 1: 核对现有模型、确定内容契约并研究历史样板来源
- [ ] Phase 2: 实现数据模型、迁移、导入契约和清河垂直切片内容
- [ ] Phase 3: 实现防剧透故事导读 / 历史背景 API 与契约
- [ ] Phase 4: 实现双模式时间线、导读阅读体验和历史背景卡
- [ ] Phase 5: 补齐单元、真库、迁移、E2E、视觉与安全验证
- [ ] Phase 6: 完成差异审阅、路线图同步与交付

## Concrete Acceptance Criteria

1. `/timeline` 保留完整事件模式，并能切换到同页的“跟着故事读”。
2. 清河主线包含 8—10 个经过人工编排的关键节点，而不是把全部事件原样再列一次。
3. 每个节点说明叙事角色、发生了什么、为什么重要、如何承接、留下什么问题，并复用人物、关系和来源入口。
4. 至少一个关键事件展示 2—3 张历史背景卡；每张卡显示事实类型、关联性质、编辑说明和独立来源。
5. 历史背景与剧情事件使用独立实体；不把社区分析直接标成历史事实。
6. 降低剧情进度时，受限导读节点、标题、说明、历史卡和来源都从 API 与界面中消失。
7. 导入校验拒绝悬空事件、悬空来源、重复顺序和缺失历史证据。
8. 新迁移可 upgrade / downgrade / upgrade；真实清河数据可重复导入。
9. Lint、类型检查、Web/API 测试、生产构建、隔离 E2E 和依赖审计通过。

## Decisions Made

- 不新增第二个导航页面；在现有时间线中增加阅读模式，避免重复信息架构。
- 第一版只做一条“清河主线导读”和一个历史背景样板事件，先验证叙事闭环。
- 故事导读引用现有 `StoryEvent`，只新增编排与导读字段，不复制事件事实。
- 历史背景使用独立实体与显式关联；一条历史来源可以支撑多个背景或关联，不沿用 `Source` 的单主体限制。
- 所有新增内容沿用 `visible_after_progress`、`spoiler_level`、发布状态与来源展示安全规则。
- 前端延续现有“玄卷档案”视觉体系，采用章节卷轴、幕次标识和阅读进度，不引入另一套品牌风格。

## Errors Encountered

- 既有清河数据将中渡桥叙事写为“945 年、20 万守桥、事先勾结并蓄意害死王清”。正史核验后确认年份应为 946；兵力有十万/二十万分歧且属于投降人数；“拒援后谋降”可证，“此前勾结并蓄意害死”不可证。本轮以事实边界重写并保留史料分歧。

**Currently in Phase 2** — 历史样板已完成来源核验，正在实现模型、迁移、导入内容和防剧透 API；前端阅读模式同步开发，待最终契约合流。
